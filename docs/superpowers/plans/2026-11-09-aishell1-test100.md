# AISHELL-1 Test-100 Development Baseline Implementation Plan

> **For agentic workers:** Execute each task in order. The data download happens only after the fixed-selection policy is recorded.

**Goal:** Create a frozen 100-utterance AISHELL-1 official-test subset and a reproducible WeNet CER evaluation path without tuning model or decoder settings.

**Architecture:** Linux stores the ignored AISHELL-1 audio archive and extracted corpus under `data/aishell1/`. Windows tracks a project-owned selector, a frozen public metadata manifest, a WeNet wrapper, and a run record. The wrapper derives machine-local paths at execution time, invokes the official recognizer, and calls WeNet's official character-error calculator.

**Tech Stack:** Python 3.10+, standard-library `csv`, `json`, `random`, `wave`, WeNet official `recognize.py` and `tools/compute-wer.py`.

## Global Constraints

- Use only the official AISHELL-1 `test` split; never use prediction or CER to change membership.
- Select exactly 100 records: lexicographically sort utterance IDs, then sample without replacement with `random.Random(20261109)`.
- Keep the checkpoint, config, `ctc_greedy_search`, beam size, and GPU selection unchanged from the successful smoke test.
- Do not upload audio, extracted data, model weights, logs, environments, or absolute Linux paths to Git.
- Label the result as an in-domain development baseline, not a generalization claim or final leaderboard result.
